# 안전보건 법령 모니터

관심 법령의 **개정 이전·현행·시행예정** 버전을 선택하고, 두 버전의 조문을 비교하는 개인용 웹 프로그램입니다.

## 윈도우에서 실행 (처음 사용하는 경우)

1. https://www.python.org/downloads/windows/ 에서 지원 중인 Python 3.12 이상 버전을 설치합니다. 설치 화면에 `Add python.exe to PATH`가 있으면 선택하세요.
2. GitHub 저장소의 **Code → Download ZIP**을 선택하고 다운로드한 ZIP의 **압축을 풉니다**.
3. 압축을 푼 폴더의 **`setup_windows.cmd`**를 더블클릭합니다. 최초 설치 때만 필요하며 인터넷 연결이 필요합니다.
4. 설치 완료 후 **`run_windows.cmd`**를 더블클릭합니다.
5. `1`은 실제 API, `2`는 가상 예시입니다. 실제 모드에서는 법제처 인증값을 입력합니다. 입력 내용은 화면에 보이지 않으며 파일에 저장되지 않습니다.
6. 브라우저가 자동으로 열립니다. 실제 모드에서는 **지금 확인**을 누릅니다. 실행 창을 닫으면 서버도 종료됩니다.

법제처의 계정 승인·호출 서버 등록 조건이 충족되어야 실제 조회가 됩니다. 윈도우에서 실행하면 법제처 요청은 이 PC가 사용하는 인터넷 연결을 통해 나갑니다. 이 방법은 본인 PC에서 실행하는 것이며 인터넷 공개 배포가 아닙니다. 기존 클라우드의 인증값은 PC에 자동 복사되지 않습니다.

설치나 실행 오류가 나면 인증값을 제외한 오류 메시지를 확인하세요. 회사 PC에서 실행이 제한되는 경우 회사 정책을 따라야 합니다.

## 실행

Python 3.12 이상을 사용합니다. Windows, Linux, macOS를 지원합니다. SQLite와 파일 잠금은 웹 조회와 정기 조회가 중복 실행되지 않도록 합니다.

```bash
cd /workspace/LAW-UPDATE-PROGRAM
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.lock

# 인증 없이 화면을 확인하는 가상 예시 모드
.venv/bin/python -m app --demo
```

서버는 기본적으로 로컬 주소의 8000 포트에서 실행됩니다. 터미널의 서버 실행 정보를 확인해 브라우저로 접속하세요. 예시 본문은 실제 법령이 아니며 화면에 가상 자료임을 표시합니다. `Ctrl+C`로 종료합니다.

실제 자료를 사용하려면 예시 서버를 종료한 뒤, 실행 환경의 보안 설정으로 **`LAW_OC`**를 제공하고 다음을 실행하세요. 인증값을 소스·명령어 인자·Git에 넣지 마세요. 코드가 `.env`를 자동 로드하지는 않습니다.

```bash
.venv/bin/python -m app
```

- `LAW_OC`: 국가법령정보 공동활용에서 발급·승인받은 API 인증값
- 네트워크: `www.law.go.kr` HTTPS 허용 필요. 문서는 `open.law.go.kr` 사용
- API 이용 범위: 시행일 기준 법령 목록과 본문, 연혁 및 시행예정 정보에 대한 이용 권한 확인
- DB 기본 위치: `.data/laws.sqlite3`. 예시 모드는 `.data/demo.sqlite3`로 분리
- `LAW_WEB_DB` 또는 `--db /절대/경로.sqlite3`로 웹 DB 위치 변경 가능
- `--port 8001`로 포트 변경 가능

이 프로그램은 로그인 기능이 없는 개인용 도구이며 기본적으로 로컬 인터페이스에만 바인딩합니다. 사내 여러 사용자가 쓰는 서버 배포에는 인증·접근 제어를 추가해야 합니다.

## 사용 순서

1. 실제 모드에는 산업안전보건법, 시행령, 시행규칙, 산업안전보건기준에 관한 규칙을 기본 등록합니다.
2. 검색해서 관심 법령을 추가합니다. 인증 전에는 정확한 법령명으로 직접 등록할 수도 있습니다.
3. **지금 확인**을 눌러 버전과 본문을 수집합니다. 진행 상태와 법령별 결과를 조회 기록에서 확인합니다.
4. 법령 상세에서 **개정 이전 / 현행 / 시행예정** 탭을 선택합니다. 여러 버전은 공포일·시행일을 보고 선택합니다.
5. 두 버전을 선택하고 **비교**를 누르면 신설·삭제·수정 조문을 나란히 확인할 수 있습니다. 변경 조문만 보기와 부칙 비교를 제공합니다.
6. 다음 수집부터 새 버전 또는 동일 버전의 본문 변경을 기록합니다. 조회 기록 옆의 CSV 다운로드로 변경 이력을 내려받습니다.

관심 해제는 수집 자료와 변경 이력을 삭제하지 않습니다. 다시 같은 법령을 등록하면 기존 이력을 이어서 사용합니다. CSV는 전체 변경 이력을 내보내며 관심 해제한 법령 이력도 포함합니다. 화면에는 조회 기록 최근 50건을 표시합니다.

## 버전과 변경의 의미

- 과거 법령은 프로그램 설치 이후 이력만 쌓는 방식이 아니라 **법제처 연혁 목록에서 수집**합니다.
- 버전 키는 법령 마스터 번호와 시행일의 조합입니다. 같은 공포본의 시행일별 버전을 구분합니다.
- `target=eflaw`, `nw=1/3/2`로 연혁/현행/예정을 조회합니다. 본문은 `MST`와 `efYd`로 특정하며, 최신 본문으로 바뀔 수 있는 `ID` 단독 조회를 사용하지 않습니다.
- 구분은 **마지막 성공한 API 조회 기준**입니다. 임의의 과거 기준일을 입력해 적용법을 판단하는 기능은 포함하지 않습니다.
- 최초 수집은 비교 기준 등록이며 새 개정 알림을 만들지 않습니다.
- 새 버전 발견일은 공식 공포일·시행일과 별개로 기록합니다. 관심 목록에 처음 나타난 과거 버전도 ‘새 버전 발견’일 수 있습니다.
- 기존 버전이 최신 목록에 없으면 ‘최신 목록 미확인’으로 보존하고 현행으로 단정하지 않습니다.
- 본문 변경 이력은 원본 JSON과 함께 보존하며, 변경 당시의 두 본문도 비교할 수 있습니다.
- 일부 조문은 시행일이 다를 수 있습니다. **부칙·적용례·경과조치와 공식 원문을 확인**해야 합니다.
- 조문 번호를 기준으로 대응시킵니다. 번호 이동·분할·통합은 자동 판단하지 않습니다.
- 별표·서식 첨부 파일의 다운로드·비교, 고시 등 행정규칙, 이메일 알림은 현재 범위에 포함하지 않습니다. 별표 등은 공식 원문에서 확인하세요.

## 정기 조회

웹 서버를 켜지 않아도 같은 DB로 조회할 수 있습니다.

```bash
.venv/bin/python -m app.monitor
# 별도 DB를 사용한다면 웹과 같은 경로 지정
.venv/bin/python -m app.monitor --db /절대/경로/laws.sqlite3
```

프로세스 종료 코드는 성공 0, 일부/전체 실패 1, 이미 조회 중 2입니다. 인증값은 이 프로세스에도 제공되어야 합니다. 원하는 시간대의 cron 또는 작업 스케줄러에 등록하세요. 예약 작업을 자동으로 설치하지는 않습니다.

cron 예시(머신의 시간대 기준 매일 09:00, 인증값은 스케줄러 환경에서 안전하게 제공):

```cron
0 9 * * * cd /workspace/LAW-UPDATE-PROGRAM && .venv/bin/python -m app.monitor >> .data/monitor.log 2>&1
```

법령별 필요한 목록과 본문을 모두 수집한 뒤 한 트랜잭션으로 저장합니다. 해당 법령의 수집이 실패하면 기존 기준과 마지막 성공 시각을 유지하고 다른 법령은 계속 조회합니다. 웹과 예약 명령은 같은 파일 잠금을 사용합니다. 초기 연혁 수집은 법령의 버전 수에 따라 시간이 걸릴 수 있습니다.

## 검증

```bash
.venv/bin/python -m unittest discover -s tests -v
.venv/bin/python -m pip check
node --check app/static/app.js  # Node가 있는 경우
```

테스트는 가상 API 응답으로 연혁/현행/예정, 조문·부칙 파싱, 비교, 최초 등록, 변경 감지, 본문 복귀, 실패 시 보존, 잠금과 변경 이력 CSV를 검증합니다. **실제 API 인증을 통한 통합 검증과는 다릅니다.**

공식 시행일 목록·본문 가이드의 요청 파라미터를 확인해 구현했습니다. 인증값을 등록한 뒤 실제 `지금 확인`을 성공시키고 버전과 본문이 일치하는지 확인해야 운영 자료로 사용할 수 있습니다. 식별자나 날짜가 맞지 않는 응답은 저장하지 않습니다. 계정/응답 구조에 차이가 있으면 `app/law_api.py` 어댑터 조정이 필요합니다.

공식 문서:
- https://open.law.go.kr/LSO/openApi/guideResult.do?htmlName=lsEfYdListGuide
- https://open.law.go.kr/LSO/openApi/guideResult.do?htmlName=lsEfYdInfoGuide

## 코드

- `app/main.py`: 웹 API와 입력 검증
- `app/law_api.py`: 법제처 검색·본문 어댑터, 조문 파싱
- `app/services.py`: 수집·변경 감지·조문 비교·중복 실행 방지
- `app/database.py`: SQLite 스키마
- `app/static/`: 한국어 웹 화면, 외부 CDN 사용 없음
- `app/demo.py`: 격리된 가상 예시 자료
- `app/monitor.py`: 예약 실행용 명령
- `tests/test_web.py`: 웹·저장·API 계약 테스트

이전 `law_monitor.py`는 독립된 메타데이터 CLI 시제품으로 보존했습니다. 웹 DB와 연동되지 않으므로 새 작업에는 `python -m app.monitor`를 사용하세요.

## 설치 없이 보는 단일 HTML 화면

저장소 루트의 **`index.html`** 하나를 내려받아 브라우저에서 열면 됩니다. CSS와 JavaScript가 파일 안에 포함되어 Python 설치, 웹 서버, 외부 CDN 없이 동작합니다.

- 개정 이전·현행·시행예정 선택, 조문·부칙 비교, 예시 법령 필터
- 모든 법령명·본문·날짜는 **가상 예시**이며 실제 법제처 API 조회나 정기 모니터링은 하지 않습니다.

인터넷 주소로 공유하려면 저장소의 **Settings → Pages → Deploy from a branch → main / (root) → Save**를 선택하세요. GitHub Pages가 배포되면 Pages 설정에 실제 접속 주소가 표시됩니다. GitHub의 파일 보기 화면은 HTML 실행 화면이 아니므로, 다운로드해 열거나 Pages로 게시해야 합니다.

기존 Python 웹 프로그램과 단일 HTML 예시는 서로 별개로 동작합니다. 실제 API 인증값을 HTML에 넣지 마세요.
